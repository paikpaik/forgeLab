테스트 방법

  1. 해피 패스 — 로그인 후 widget-plenty로 체크아웃하면 ORDER_TRIED → INVENTORY_TRIED → CONFIRMED 순서로 몇 초 안에 전이됩니다(orchestrator가 2초 간격 폴링으로 saga를 진행시킵니다).
  2. 보상 트랜잭션 — widget-scarce 재고를 0으로 만든 뒤(먼저 체크아웃 1건으로 소진시키거나 "리셋"으로 0을 넣고) 다시 체크아웃하면, order Try는 성공하지만 inventory Try가 실패해서 COMPENSATING → CANCELLED로 갑니다 — 이때 order-service에 실제로 CancelOrder gRPC 호출이 나갑니다.
  3. 다중 인스턴스 정합성 — "widget-scarce 재고를 1로 리셋" 후 "동시 체크아웃 2건 발사"를 누르면, inventory-service 2개 인스턴스 중 어디로 요청이 가든 정확히 1건만 CONFIRMED로 가고 나머지 1건은 CANCELLED로 갑니다(재고가 마이너스로 내려가지 않음).
  4. 인가(authorization) — "인가 실패 재현"을 누르면 customer 토큰으로 admin 전용 리셋을 시도해서 403이 로그에 찍히는 걸 확인할 수 있습니다.
  5. 각 프로세스의 /health, /metrics — gateway :3300/health, orchestrator :3301/health, order-service :3302/health에서 확인 가능합니다(inventory-service는 호스트 포트를 노출하지 않습니다 — 2인스턴스라 고정 포트 매핑이 불가능해서 내부 네트워크에서만 접근).

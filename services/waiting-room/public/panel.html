테스트 방법

  1. 순서/폴링 확인 — "줄서기"를 누르면 me-xxxxx 형태의 유저로 즉시 등록됩니다. 내 티켓 카드의 숫자가 몇 번째인지, 전체 대기열 그리드의 초록 칸(내 티켓)이 어디 있는지 1초마다 갱신되는 걸 확인하세요.
  2. admission 확인 — 서버는 기본 5초마다 앞쪽 10명을 자동으로 입장 허용 처리합니다(ADMISSION_INTERVAL_MS/ADMISSION_BATCH_SIZE 환경변수). 잠시 기다리면 대기 인원이 계단식으로 줄고, 내 티켓이 "입장 가능!"으로 바뀌는 걸 볼 수 있습니다.
  3. 버스트(동시 접속) 확인 — 인원수(예: 50)와 분산시간(예: 0ms = 완전 동시, 2000ms = 2초에 걸쳐 분산)을 넣고 "한번에 등록"을 누르세요. 대기 인원이 한 번에 확 쌓였다가, admission 주기마다 정확히 배치 크기만큼 빠지는 걸 이벤트 로그와 그리드로 동시에 확인할 수 있습니다.
  4. 버스트 중지 — 등록이 끝난 뒤에도 버튼은 "대기열에서 빼기"로 이름이 바뀌며 계속 떠 있습니다. admission이 다 빠질 때까지 기다리기 싫으면 언제든 눌러서 이 버스트가 등록한 사람만 대기열에서 바로 제거하세요("내 티켓"으로 따로 등록한 건 안 지워집니다).
  5. 중복 등록 에러 확인 — 같은 유저로 "줄서기"를 두 번 시도하면(브라우저 콘솔에서 같은 userId로 POST) E9409 에러가 나는 걸 API 응답으로 확인할 수 있습니다.
  6. 초기화 — 테스트를 반복하고 싶으면 "초기화" 버튼으로 대기열과 입장 허용 기록을 전부 지우고 처음부터 다시 시작할 수 있습니다.
  7. 관측 지표 — /metrics에서 Prometheus 포맷으로 큐 길이(waiting_room_queue_length), 평균 대기시간(waiting_room_wait_time_ms), 누적 admission 수(waiting_room_admissions_total)를 직접 볼 수 있습니다.

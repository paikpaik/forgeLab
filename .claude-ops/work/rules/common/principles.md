# 원칙 — 임의 결정 금지, forge는 제안서로

## 결정하지 않은 것을 임의로 정하지 않는다

저장소 구조, 워크스페이스 경계, 서비스 간 통신 방식처럼 되돌리기 어려운 결정은 먼저 사용자와 확인한다. 반대로 특정 실험 내부의 파일 구성처럼 순수 기술적이고 되돌리기 쉬운 결정은 합리적으로 제안하고 진행해도 된다.

## forge 패키지는 수정하지 않고 제안서로 남긴다

`node-forge`/`kafka-forge`에 부족하거나 확장이 필요한 기능을 발견해도 `forge/` 아래 소스를 직접 고치지 않는다. `proposals/<패키지명>/`에 제안서를 작성해서 무엇이 부족한지, 왜 필요한지, 어떤 API를 제안하는지 정리한다. 실제 반영과 배포는 사용자가 각 forge 레포로 가져가서 진행한다.

## 필요 이상으로 확장하지 않는다

첫 실험(waiting-room)의 요청받은 범위만 구현한다. 다음 실험을 미리 가정한 공통 추상화를 만들지 않는다 — 두 번째 실험이 실제로 시작될 때 공통점을 추출한다.

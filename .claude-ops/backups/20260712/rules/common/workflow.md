# 워크플로우 — 설계 확인 후 구현

## 코딩 전에 설계를 먼저 확인한다

새 실험(서비스)이나 구조 변경이 필요한 작업은, 코드를 짜기 전에 설계안(디렉토리 구조, 핵심 타입/API, 트레이드오프)을 먼저 정리해서 사용자 확인을 받는다.

## 새 작업은 `/harness-plans`로 기록한다

실험 단위 작업을 시작하기 전 `.claude-plans/`에 플랜을 남기고, 완료 후에는 실행 이력을 추가한다.

## forge 부족 기능을 발견하면 제안서부터

구현 중 `node-forge`/`kafka-forge`에 없는 기능이 필요하면, 작업을 멈추고 먼저 `proposals/`에 제안서를 작성한 뒤 사용자에게 알린다. 우회 구현으로 조용히 넘어가지 않는다.
